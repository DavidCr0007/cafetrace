# C4 — CaféTrace IA

## Contexto

El consumidor consulta el catálogo y el pasaporte de lote. Productores registran lotes y dispositivos. Administración opera pedidos, logística, IoT y auditoría. FastAPI persiste en PostgreSQL y, cuando está configurado, firma transacciones hacia `CafeTraceRegistry` en Polygon Amoy.

## Contenedores

```text
[Consumidor/Productor/Admin] -> [Next.js] -> [FastAPI]
                                      |          |-- PostgreSQL
                                      |          |-- Open-Meteo (Icononzo)
                                      |          |-- Polygon RPC -> CafeTraceRegistry
                                      |          |-- IoT HTTPS gateway
```

## Límites

La clave privada blockchain vive únicamente en el backend/runtime secret manager. Tokens IoT se almacenan como SHA-256. El frontend nunca firma notarizaciones ni recibe la clave privada.

## Componentes del backend

FastAPI se organiza como monolito modular en `backend/app/modules/`: `identity`,
`audit`, `traceability`, `blockchain`, `catalog`, `orders`, `payments`,
`logistics`, `accounting` e `insights`. Cada módulo agrupa sus modelos, esquemas,
servicios y routers; la dependencia entre módulos pasa por sus servicios y modelos
públicos, no por rutas HTTP internas.
